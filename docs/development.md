# การพัฒนา ปัญหาที่พบ และข้อจำกัด

## วิธีที่เราทำ

1. **กำหนดรูปแบบเกม:** แบ่งผู้เล่นเป็นคนอยู่กับเครื่องและคนถือคู่มือ กำหนด 5 ด่าน เวลา 5 นาที และจำนวนครั้งที่พลาดได้
2. **สร้างเครื่องต้นแบบ:** ต่อ Arduino UNO R4 WiFi กับจอ LCD, buzzer และปุ่มกด 4 ปุ่มบนเบรดบอร์ด
3. **เขียนโปรแกรม:** แยกส่วนสุ่มลำดับด่านและตรวจคำตอบออกจากส่วนแสดงผล เล่นเสียง และอ่านปุ่ม จากนั้นรวมเข้ากับระบบเวลาและ strike
4. **ออกแบบคู่มือ:** เขียนกฎของสัญลักษณ์ทั้งห้าให้คนที่ไม่เห็นเครื่องใช้ถอดรหัสจากคำบอกของเพื่อนได้
5. **ทดสอบการเล่น:** ลองความยากของโจทย์และการสื่อสารระหว่างผู้เล่น เพื่อนำไปปรับจังหวะและกติกาของเกม

[ดูโครงสร้างซอร์สโค้ด](software.md) · [ดูเครื่องต้นแบบและการต่ออุปกรณ์](hardware.md)

## อุปสรรคและการเปลี่ยนวิธี

แผนแรกมีระบบเพิ่มแรงกดดันอีกสองส่วน ได้แก่ **เวลาเดินเร็วขึ้นเมื่อกดผิด** และ **เหตุการณ์สุ่มระหว่างข้อ** ซึ่งเป็นโจทย์วัดไหวพริบสั้น ๆ ถ้าตอบถูกจะไม่เพิ่มจำนวนด่านหลัก แต่ถ้าตอบผิดจะนับเป็นการพลาด

เมื่อนำส่วนเหล่านี้มารวมกับเกมหลัก ระบบยังมีบัค และเวลาแก้ไขก่อนส่งงานเหลือน้อย เราจึงตัดทั้งสองส่วนออก แล้วเน้นให้การสุ่มด่าน เสียง ปุ่ม จอ เวลา และการตรวจคำตอบของเกมหลักทำงานร่วมกันก่อน

## ผลที่ได้ในรุ่นปัจจุบัน

| ทำได้แล้ว | ยังไม่รวมในรุ่นนี้ |
| --- | --- |
| เล่นเกมหลักครบ 5 ด่าน | เร่งความเร็วของเวลาเมื่อกดผิด |
| สุ่มลำดับสัญลักษณ์และสร้างลำดับเสียง | เหตุการณ์สุ่มที่คั่นระหว่างข้อ |
| แยกเสียงจริงกับเสียงหลอกตามกฎ |  |
| รับปุ่ม ตรวจคำตอบ และนับ strike |  |
| แสดงสถานะบน LCD และแจ้งผลด้วยเสียง |  |
| จบเกมเมื่อผ่านครบ เวลาหมด หรือผิดครบ 3 ครั้ง |  |

หากจะเพิ่มสองระบบที่ตัดออกกลับมา ควรแยกทดสอบเหตุการณ์สุ่มกับระบบเวลาให้เสถียรก่อน แล้วจึงทดสอบร่วมกับกติกาหลักอีกครั้ง

> **ภาพประกอบที่ควรเพิ่ม:** ภาพช่วงต่อวงจรหรือภาพเปรียบเทียบรุ่นทดลองกับต้นแบบปัจจุบัน หากทีมมีภาพจริง
